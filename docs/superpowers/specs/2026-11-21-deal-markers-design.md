# Deal markers on map pins — design

> **Status:** Draft 2026-11-21, awaiting approval. Needs a new decision entry (P-015) and a proposed CONTRACTS.md change (§8). Touches workstream A (map/cards) and the pipeline.

## Intent

Vibenta is for Boston college students, and saving money is one of the main things they look for. PRODUCT.md promises "verified discounts" and ROADMAP M8 lists "verified inexpensive places/discount descriptions with timestamps". This feature puts a small marker on a pin **when you can get a discount there right now**. The place card lists the venue's deals with where each one came from and when it was checked.

The marker means one thing only: *active now*. A marker for an expired, stale or unconfirmed deal is worse than no marker.

## Goals

- Store two kinds of deal per catalog place:
  - **Standing student discounts**, e.g. "10% off with student ID".
  - **Time-based specials**, e.g. happy hour or "half-price pizza Tuesdays".
- Fill them from three free sources: a hand-checked list, the OSM `happy_hours` tag, and a rule-based scan of venue websites.
- Show a marker on a pin while at least one of its deals is active. Update it every minute while the map is open.
- Add a **Deals** section to the place card with each deal's text, schedule, status, source link and checked date.

## Non-goals

- Groupon, UNiDAYS, Student Beans or other affiliate feeds. They need partner approval.
- Any LLM or paid API, including Gemini. The user chose the cheapest option.
- Student-submitted deals. That's a later step, tied to Student Pulse.
- A "has deals now" filter or sorting by deals.
- Parsing venue opening hours. See "Active rules".
- Deals for non-catalog places (Overpass parks, museums and so on).

## Anti-goals (failure even if it "works")

- A marker on a deal that isn't on right now, or one we haven't checked in over 90 days.
- A schedule shown as confirmed when the source didn't state one clearly.
- Invented or placeholder deals in the hand-checked list, or anywhere a student would see them (AGENTS.md §5).
- Copying long text from venue sites. We store a short quote only.

## Constraints

- Follow source terms. Website fetching uses the existing `PoliteFetcher` (`pipeline/src/media/http.ts`): pipeline User-Agent, robots.txt checks, per-host spacing, timeouts.
- No new paid services. No new dependencies unless already in the repo (`node-html-parser` is).
- Times are Boston local (`America/New_York`). Use `apps/web/src/discovery/bostonTime.ts` on the web side.
- The browser uses the publishable key and reads through RLS. Writes come from the pipeline with the secret key.
- Workstream ownership (WORKSTREAMS.md): the pins and card in `apps/web/src/main.ts` belong to the map owner. The shared `Place` type belongs to integration. Both need sign-off.

## Approaches

Considered for the data source:

- **Venue websites read by Gemini.** Best recall, but it costs money per run. Rejected by the user: keep it as cheap as possible.
- **Groupon and other affiliate feeds.** Gated behind partner approval: Groupon's partner APIs closed in 2022 and its deal feed goes through CJ affiliate approval. They're also mostly vouchers, not standing student deals. Rejected.
- **Yelp / Google.** Their data can't be stored (P-007, P-008). Rejected.
- **Student submissions.** Fits Student Pulse but starts empty and needs moderation. Deferred.
- **Chosen:** a hand-checked list as the trusted core, the OSM `happy_hours` tag as a free extra, and a rule-based (no AI) website scan for reach. All three write one table, with a `source` column.

The user also clarified that the every-minute marker update is a client-side clock check against stored schedules. It makes no network calls.

## Design

### 1. Data: `place_deals` table (new migration)

```sql
create table public.place_deals (
  id             bigint generated by default as identity primary key,
  restaurant_id  bigint not null references public.restaurants (id) on delete cascade,
  kind           text not null check (kind in ('student', 'special')),
  title          text not null check (char_length(title) <= 120),  -- card line, e.g. "10% off with student ID"
  quote          text check (char_length(quote) <= 200),          -- exact source text the deal was read from; null for curated
  schedule       jsonb,                -- see §2; set only when timing = 'scheduled'
  timing         text not null check (timing in ('any_time', 'scheduled', 'unconfirmed')),  -- see §2
  check ((timing = 'scheduled') = (schedule is not null)),
  check (kind = 'student' or timing <> 'any_time'),
  source         text not null check (source in ('curated', 'osm', 'website')),
  source_url     text,                 -- page the deal came from; required for curated and website
  checked_at     timestamptz not null, -- when we last saw the deal at its source
  hidden         boolean not null default false,  -- team removes a bad row without deleting it
  created_at     timestamptz not null default now(),
  check (source = 'osm' or source_url is not null)
);
create index place_deals_restaurant_idx on public.place_deals (restaurant_id) where not hidden;
alter table public.restaurants add column deals_checked_at timestamptz;  -- when enrich:deals last scanned this place's website
```

RLS: anyone can `select` rows where `hidden = false`. There are no client writes.

The `quote` is public but capped at 200 characters. It lets a reader or teammate see exactly what the deal was based on. Crawled page text otherwise stays in the private `place_vibe_inputs` table (*my call*).

### 2. Schedule format

`timing` says what we know about when a deal runs:

- **`any_time`** (student only): the source gives no timing at all. It's a standing discount, e.g. "10% off with student ID".
- **`scheduled`**: the source gives a schedule we parsed with confidence. `schedule` holds it.
- **`unconfirmed`**: the source mentions timing we couldn't parse, or gave no time for a special. Examples: "Student night Wednesdays", "4pm to close", "during finals week", "Happy hour daily".

*Builder-check call:* without this column, an unparsed "student night" would have counted as a standing discount and shown a marker around the clock.

`schedule` is a JSON array of windows, in Boston local time:

```json
[{ "days": [1, 2, 3, 4, 5], "start": "16:00", "end": "18:00" }]
```

- `days`: 0 = Sunday … 6 = Saturday. Must be non-empty.
- `start` / `end`: `"HH:MM"` in 24-hour time.
- If `end <= start`, the window runs past midnight and belongs to the day it starts on. For example, Friday 22:00–01:00 is active until 01:00 Saturday.
- No "until close" or open-ended windows. A source saying "4pm to close" gets `timing = 'unconfirmed'`.

### 3. Active rules (shared by the pin and the card)

A deal is **active now** when it is not hidden, `checked_at` is within the last 90 days, and one of these holds:

- `timing = 'any_time'`. Nothing records venue hours yet (`restaurants.hours` is never filled and `hours_raw` isn't parsed), so the agreed "hours unknown → still show" rule applies. In practice, standing student discounts are always active. When hours parsing lands, add "and the venue is open, if its hours are known".
- `timing = 'scheduled'` and the current Boston wall time falls inside one of its windows. This applies to both kinds; a student deal may have a schedule, e.g. "Student night Wed 8–11pm".

`timing = 'unconfirmed'` is **never** active, whatever the kind.

Status shown on the card:
- **"Active now"**
- **"Next: Tue 4–6pm"** — the next window start within 7 days.
- **"Times not confirmed"** — `timing = 'unconfirmed'`.
- **"Not recently checked"** — older than 90 days. The deal is listed but never marked active.

### 4. Pipeline step `npm run enrich:deals`

New entry point `pipeline/src/enrichDeals.ts`, with logic in `pipeline/src/deals/*.ts`. It follows `enrichMedia.ts` conventions: `parseArgs`, `--dry-run`, `--limit N`, `--concurrency N` (default 4), `--refresh`. It runs three stages per invocation, and each one can be skipped with `--only curated|osm|website`.

#### 4.1 Curated list

- **File:** `pipeline/deals.curated.json`, committed. It's an array of entries like:

  ```json
  { "place_id": "osm:node/123", "kind": "student", "title": "10% off with student ID",
    "schedule": null, "source_url": "https://…", "checked_on": "2026-11-21" }
  ```

- **Required:** `place_id` (the catalog's `restaurants.place_id`), `kind`, `title`, `source_url`, `checked_on`. `schedule` is optional. `checked_at` is `checked_on` at 12:00 Boston time.
- **Timing:** a schedule gives `scheduled`. A student entry without one gives `any_time`. A special without one gives `unconfirmed`. An entry may set `"timing": "unconfirmed"` explicitly, e.g. for a student night whose hours the team couldn't confirm.
- **Validation:** each entry is checked against §1 and §2. An entry whose `place_id` isn't in the catalog, or that fails validation, is reported and skipped; the run continues.
- **Write:** replace the visible `source = 'curated'` rows with the file's contents (§4.4 covers hidden rows).
- **The file ships empty (`[]`).** The team fills it with deals they have confirmed themselves. The builder adds no entries. Test data lives in test fixtures only.

#### 4.2 OSM `happy_hours`

- Add `happy_hours` to the kept OSM tags in `pipeline/src/normalize.ts` (the list at line 105), so it lands in `restaurants.osm_tags`. It appears after the next `npm run ingest`.
- Parse a subset of opening_hours syntax:
  - day ranges and lists (`Mo-Fr`, `Mo,We`, `Sa-Su`);
  - one or more time ranges (`16:00-18:00`, `16:00-18:00,22:00-24:00`);
  - `;`-separated rules.
- Anything outside that subset (`PH`, month ranges, `sunset`, comments) gives `timing = 'unconfirmed'`.
- **Rows written:** `kind = 'special'`, `title = "Happy hour"`, `quote` = the raw tag value, `source_url` null.
- **`checked_at`:** the place's `restaurants.last_seen_at`, i.e. when ingest last saw the tag in OSM. It is not the deals run time, which would keep a stale tag looking fresh past 90 days *(builder-check call)*.
- **Write:** replace the place's visible `osm` rows.

#### 4.3 Website scan (rule-based, no AI)

**Which places:** catalog places with a `website` whose `deals_checked_at` is null or older than 7 days. `--refresh` scans all. Places whose website is a third-party host (Facebook, Instagram, Yelp and others in `THIRD_PARTY_HOSTS`, `media/website.ts`) are skipped, as the photo step does. Those count as a permanent failure (P-007, P-008).

**Pages per place:** at most 3, all robots-checked, through one shared `PoliteFetcher`:
1. The home page (the normalized URL, same as `scrapeWebsite`).
2. Up to 2 same-origin links whose `href` or link text matches `/special|happy[\s_-]?hour|student|deal|promo|discount/i`, in page order.

**Text:** the body text with `script`, `style`, `noscript`, `template` and `svg` removed. Headers, navs and footers are kept, since banners often carry specials. The text is split into lines on block elements and `<br>`, then into sentences.

**Matching per line** (patterns in `pipeline/src/deals/match.ts`, exported for tests):
- **Student:** a student term (`student`, `college id`, `school id`, `.edu`) **and** a discount term (`\d+\s?% off`, `\$\d+ off`, `discount`, `free`, `half[- ]price`, `deal`) in the same line. "Students welcome" alone doesn't count. Gives `kind = 'student'`.
- **Special:** `happy hour`, `half[- ]price`, `\d+\s?% off`, `bogo`, `buy one get one`, or a weekday + `special(s)`, e.g. "Tuesday specials". Gives `kind = 'special'`. A line matching both is `student`.

**Title / quote:** the matched line, whitespace-collapsed. `title` is cut to 120 characters on a word boundary, with an ellipsis. `quote` is the line up to 200 characters.

**Schedule parsing** (`pipeline/src/deals/schedule.ts`), from the matched line and the line right after it:
- **Days:**
  - `Mon–Fri` and similar ranges (en dash, hyphen, "through", "thru", "to");
  - full or short day names, with plurals ("Tuesdays");
  - `weekdays` → 1–5; `weekends` → 0, 6; `daily` / `every day` → 0–6.
- **Times:** `4–6pm`, `4pm-6pm`, `4:30-6:30 pm`, `16:00-18:00`, `10pm-1am`, `noon`, `midnight`.
  - An am/pm marker on the end time only applies to the start time if that yields `start < end` within 12 hours. "11-2pm" means 11:00–14:00.
  - With no am/pm and no 24-hour clock anywhere, there's no schedule.
- **Results:**
  - Days but no time → no schedule.
  - A time but no days → `daily` if the line says "daily", else no schedule.
  - "Close", "late" or "till close" as the end → no schedule.
- When parsing isn't confident, `timing = 'unconfirmed'`. Never guess.
- **One-off dates:** text containing a month name or abbreviation, a numeric date, a year or a holiday word (Thanksgiving, Christmas, Black Friday and similar) never yields a schedule.
- **Student lines with no schedule:** `any_time` only when both of these hold, otherwise `unconfirmed` (still listed on the card, no chip):
  - the line and the next contain **no** "not safe to treat as standing or weekly" words: day names; `weekday(s)`, `weekend(s)`, `week*`, `daily`, `every day`; `*night(s)`; `lunch*`, `dinner*`, `brunch*`, `breakfast`, `evening`, `morning`, `afternoon`, `late`, `tonight`, `today`, `after`, `before`; `hour*`, `semester(s)`, `final(s)`; `until`, `till`, `through`, `thru`, `end(s)`, `expire(s)`, `valid` (except in "valid student ID"), `limited`, `season`, `holiday`, `only`; month names, numeric dates and years; `am`, `pm` or any time;
  - the line has a **concrete offer** (ruling R7, a deliberate tightening of the broad discount terms above): `N% off`, `$N off`, `half-price`, "free <something> with (a) (valid) student/college/school ID", or "student discount/price/pricing/rate(s)". "Free Wi-Fi for students" or "Great deals for students!" are still read as `student` deals, but never get an any_time chip.

**Limits:** at most 5 deals per place from the website, de-duplicated by lower-cased title.

**Write:** replace the place's visible `website` rows, then set `deals_checked_at`. Page failures:
- **Transient** (`timeout`, `network`) on **any** of the place's pages: keep all existing rows and don't set `deals_checked_at`, so the next run retries. Partial results are never written over a fuller earlier scan *(builder-check call)*.
- **Permanent on the home page** (`robots`, `http`, `not_html`, `third_party`): clear the visible rows and set `deals_checked_at`.
- **Permanent on a linked page only:** carry on with the pages that loaded.

**`--dry-run`:** writes nothing to the database. It writes `pipeline/.cache/deals-dry-run.json` (place, page, line, parsed kind/title/schedule) so the team can spot-check matching before a real run.

**Ordering:** the photo pipeline's tiers (`media/priority.ts`: demo places, then near campuses and stops) come first, so a partial run covers the places students see.

#### 4.4 Hidden rows (all sources)

Same pattern as the photo pipeline (`media/db.ts` deletes only `hidden = false` rows). *Builder-check call.*

- **No run deletes a hidden row.** "Replace" always means replacing the place's visible rows from that source.
- **Hidden rows stay hidden:** before inserting, a new row is dropped if a hidden row exists for the same place and source with the same **match key**.
  - **Website and OSM:** the match key is the `quote`, lower-cased with whitespace and punctuation collapsed.
  - **Curated:** the match key is the `title`.
- **The trade-off:** if a venue rewords the text, the new row shows and the team hides it again. That's accepted: rewording usually means the deal changed.

### 5. Web: loading deals (`apps/web/src/catalog.ts`)

- Add `place_deals(kind, title, timing, schedule, source, source_url, checked_at)` to the details query as a PostgREST embedded select through the foreign key. RLS already filters out hidden rows.
- `CatalogDetails` gains `deals: Deal[]`. `pinToPlace` carries them on the map `Place` as a new optional `deals?: Deal[]` field on the `Place` type in `apps/web/src/osm.ts`. They don't go in `tags`: `tags` is string-only, and a schedule is structured.
- If the embed fails, `deals` is empty and the rest of the details still load.

### 6. Web: active logic (`apps/web/src/deals.ts`, new, pure)

- `isActive(deal, now: Date): boolean` — the rules in §3.
- `dealStatus(deal, now): { kind: 'active' } | { kind: 'next', label: string } | { kind: 'unconfirmed' } | { kind: 'stale' }`.
- `activeKinds(deals, now): Set<'student' | 'special'>`.
- Uses `bostonWallTime` from `discovery/bostonTime.ts`, so it's correct whatever the device's time zone.

### 7. Web: pin marker and card (`apps/web/src/main.ts`, map owner)

**Pin chip**
- Inside the pin `<button>`, add a `span.pin-deal` above the pin body. It shows `🎓` when a student deal is active, `%` when a special is, and both when both are.
- Hidden when nothing is active.
- Fixed light background and dark text with a thin outline, so it stays readable over every vibe theme and pin color (the contrast guard only covers pin colors).
- Scales with `--pin-scale`. It's a child of the pin element, so MapLibre's transform rules (the comment above `shadowElement`) still hold.

**Accessibility:** when active, the pin's `aria-label` becomes `"<name>, deal on now"`.

**Ticking**
- One `setInterval` every 60 s re-evaluates `activeKinds` for the current markers and toggles the chip.
- If the place card is open, its Deals statuses re-render too.
- The interval is cleared and recreated with `showPlaces` / `clearPins`.

**Card Deals section:** shown when `place.deals` is non-empty, after the details list. Each deal shows:
- the icon and title;
- the schedule in words, e.g. "Mon–Fri 4–6pm" or "Any time" for a standing student discount;
- the status from §6;
- a "Source" link (validated with the existing `safeHttpUrl`; OSM deals link to the OSM feature);
- "checked Nov 21".

Website-sourced deals get a small "found on venue site" note, so students know the text came from the site and wasn't confirmed by us.

### 9. States to cover

- **Catalog not configured, or details failed:** no deals and no chips; the card is unchanged.
- **Place with no deals:** no Deals section.
- **Deals, none active:** the card lists them with "Next: …", "Times not confirmed" or "Not recently checked"; no chip.
- **Active deal:** chip plus "Active now".
- **A window starts or ends while the map is open:** the chip appears or disappears within 60 s.
